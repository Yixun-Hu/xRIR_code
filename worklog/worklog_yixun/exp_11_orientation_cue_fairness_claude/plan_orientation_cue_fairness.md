Experiment identifier exp_11 (exp_10 is the peer's `yaw_pilot`).

## 1. Question

In the paper's HAA table the oriented CylindricalViT (exp_06 arm C) is pretrained and fine-tuned with an explicit loudspeaker-facing cue while the vanilla xRIR baseline is not. Does CERPA's advantage persist when the SimpleViT baselines receive the same explicit cue, and does the explicit cue by itself change the SimpleViT baselines?

## 2. Design

### 2.1 The cue, mechanically (exp_06 `plan_oriented_cyl.md` §2; code survey and Codex plan review of 2026-09-26)

1. **Heading frame (data level).** The whole scene (depth panorama, query and reference source coordinates) is rotated by `k = 128` so that the loudspeaker's inferred acoustic axis (−y in all four rooms, `ckpt/exp06/heading/*.json`, `confirmatory`) points along +x (`tools/exp06_heading.py::HeadingFrameDataset` → pinned `tools/yaw_rotation.py::rotate_scene_yaw`). This is **implicit orientation conditioning**: the heading is delivered by canonicalising the input frame. For a model pretrained at rotation 0 it is also a coordinate-frame change relative to pretraining.
2. **Azimuth planes (model level, `CylindricalViTOriented`).** Two constant input planes `cos θ_c, sin θ_c` of the camera-frame column azimuth (a pure function of the column index; they vary across the 32 pixel columns of a patch) concatenated after the gauge alignment and projected by a LayerNorm → Linear → LayerNorm patch embedding over the 5-channel patch. This is **explicit orientation conditioning**; CERPA pretrains with it from scratch.

For the SimpleViT the planes add no sample-dependent heading measurement (its fixed 2-D sinusoidal position code already fixes the token column), but they are **not** a function-preserving change: the first LayerNorm normalises geometry and azimuth jointly (the Codex review's CPU check: zero-initialising the added projection weights still moves the embeddings by up to 0.140), the projection, gradients and parameter count change (+526 336), and the physical circular azimuth differs from the token-index sinusoids. Therefore exp_06's arm D is reported as **"SimpleViT fine-tuned in the heading frame (implicit conditioning)"**, not as "xRIR + orientation cue", and the explicit-cue SimpleViT arms are built and pretrained literally (Phase 2), with a cheaper explicit-adapter control (Phase 1b) that keeps the pretrained checkpoint's function at initialisation.

Yaw augmentation (exp_04/exp_09's E) trains the SimpleViT to be insensitive to the scene's roll relative to its pinned position code during *pretraining*; HAA fine-tuning applies no augmentation, so orientation dependence can be re-learned. "G ≈ E" is therefore a prospective hypothesis (N3), not a consequence of the code; G is described precisely as "the yaw-pretrained SimpleViT fine-tuned and evaluated in the heading frame".

All four rooms share one inferred axis and one roll; the experiment compares pipelines on these fixed rooms and does not establish generalisation across loudspeaker headings.

### 2.3 New models (all in new files; every existing `model/*.py` is frozen)

- `SimpleViTOriented` (`model/simple_vit_oriented.py`): `SimpleViT(channels = 5)` with the two azimuth planes derived locally from the column grid (tested equal to `convert_equirect_to_camera_coord`'s horizontal look direction and to `CylindricalViTOriented.az_channels`); `forward = cat([img, az]) → SimpleViT.forward`; encoder parameter increment exactly 526 336 (asserted from the factory). `xRIR_SimpleOriented(xRIR)` in `model/xRIR_simple_oriented.py` with the 256-token pool guard.
- `SimpleViTAdapter` (`model/xRIR_simple_adapter.py`): wraps the **pinned** SimpleViT unchanged; a `Linear(2 → dim)` with **zero weight and zero bias** (1 536 parameters at dim 512) of the heading-relative azimuth `(cos(θ_j − φ), sin(θ_j − φ))` of each of the 16 token columns, **token-angle convention `θ_j = 2π(j + ½)/16 − π`**, φ = the bound `phi_deg` converted to radians, is **added after the patch embedding's final LayerNorm**, next to the positional code (tokens of one column share the value). Heading routing: the unchanged dataset/loss interface carries no room identifier, so the exp_11 entry points validate that every participating room's bound heading record supplies the **same** heading (all four records: `phi_deg −90`, `k 128`, confirmatory), install that shared cue, and **refuse mixed headings**; per-room conditioning is out of scope. Two loading modes, both strict: (i) initialisation from A/E — every inherited key validated strictly, only the adapter weight/bias initialised to zero (function bit-exact to the base checkpoint, tested); (ii) later stage/evaluation checkpoints — the complete adapter state required strictly (never `strict=False`, never a silently re-zeroed adapter). **Interpretation (fixed):** with one heading for all rooms, `W·a_j(φ) + b = W·R(−φ)·a_j(0) + b`, so the heading is absorbable into the learned projection; J/K test *an added learnable circular positional representation during fine-tuning*, a fair supplementary explicit-conditioning control; Q1/Q3 cannot attribute a gain to measured heading information. Registered as a different design from CERPA's five-channel pretraining.
- Simulated pretraining of `simple_oriented` (and of C) uses an **absolute azimuth anchor**; its loudspeaker-relative meaning arises only through the HAA heading transform.
- Registry `BACKBONES_EXP11 = {**BACKBONES_EXP06, 'simple_oriented': …, 'simple_adapter': …}` and `build_xrir_exp11`; the inherited routes return the pinned classes (`is`), bit-identical outputs on a fixed batch; `BACKBONES_EXP06` is never mutated (its digest is part of every completed exp_06/exp_09 child).

## 3. Pre-registered contrasts and decision rules

Machinery: exp_06 §7 (`tools/exp06_bootstrap.py`; paired per-query differences over the three fine-tuning seeds and a room's DiffRIR test queries; point estimate = mean; primary interval = converged seed-0 **two-way** 95 % percentile interval, `n_boot` 10 000, one quadrupling on a failed 0.10 convergence check; query-cluster interval reported alongside; void rule 1 % / 99 %). **Every decision-bearing field (category, non-inferiority, superiority, equivalence, interaction) is withheld when its cell is void or unconverged; equality at a decision boundary establishes nothing.** Margins apply to hallway C50 only. Unless stated, the primary cell is hallway C50; all other room × metric cells are screened.

Notation: for a contrast X − Y with interval [L, U]: **category** = detected harm for X if L > 0, detected improvement for X if U < 0, else no detected difference. **Y non-inferior to X at m** iff −L < m (equivalently the upper bound of Y − X is below m). **X's margin-sized advantage** iff U < −m. **Equivalence at m** iff L > −m and U < m ("95 % containment"; conservative relative to TOST at α = 0.05, which uses a 90 % interval; this is the rule). m = 0.23 dB (Yixun decision (d)).

**Phase 1 (G).**
- **N1** — G − D: category. Does roll-robust pretraining change what the SimpleViT does with the heading frame?
- **N1i** — interaction (G − E) − (D − A): computed with the frozen bootstrap as `paired_intervals(g − e, d − a, query_clusters, seeds)` (jointly resampled; never a subtraction of two independently bootstrapped intervals) by an exp_11 **four-arm assembler** that checks query index, IR path, protocol metadata and seed alignment across A/D/E/G, uses one query mask finite across all four arms and all three seeds, reports each arm's original exclusions, requires the joint cohort to cover ≥ 99 % of the room's test queries, and keeps the component invalidity checks of G − E and D − A. Field: category, read as "a positive interaction = a larger heading-frame penalty after yaw pretraining" (not as harm by any single arm). A degenerate (zero-width) interval — possible by cancellation; the frozen convergence helper raises on it — yields a defined **unavailable** result in the exp_11 wrapper without aborting the summary and without touching the historical helper. Disclosure: D − A was observed in exp_06 (hallway C50 +0.63 dB) before this plan; G − E was not.
- **N2** — C − G: category; G's non-inferiority to C at m; C's margin-sized advantage; reported separately.
- **N3** — G − E: category **and** equivalence at m (the prediction G ≈ E is the equivalence statement).
- **S1** — three descriptive screen families (G − D, C − G, G − E), each over the 11 room × metric cells with Bonferroni-11 adjusted two-way intervals (tails 0.05/22, `n_boot` 50 000), labels only; no experiment-wide claim across families. **exp_11 screens apply the universal void/unconverged suppression** (an exp_11-specific gate; the historical exp_06/exp_09 screen semantics are unchanged).

**Phase 1b (J, K).**
- **Q1** — J − A: category and equivalence at m (does the explicit adapter change the vanilla xRIR?). **Q2** — C − J: category, J's non-inferiority, C's advantage. **Q3** — K − E: category and equivalence. **Q4** — C − K: category, K's non-inferiority. Screens per contrast as in S1.

**Phase 2 (H, I).**
- **P3 (primary literal comparison)** — C − H: category, H's non-inferiority to C at m, C's margin-sized advantage; **the only contrast that can establish the headline claim**. **P3′** — C − I: the same fields, secondary (reported, cannot establish the headline alone; no multiplicity adjustment between P3 and P3′ because only P3 is decision-bearing).
- **P1** — H − D and **P2** — I − G: category and equivalence at m — the better-matched channel-family comparisons (HAA frame held fixed; they still include the added parameters and a different pretrained realisation).
- **P4** — H − A and **P4′** — I − E: category and equivalence; **P4 bundles the five-channel pretraining with the room-to-heading frame change** and is read as the requested pipeline-level difference, not as the channel's isolated effect.
- Screens per contrast (families as in S1).

**R1 — historical re-reports (no new inference), source-field map.** From exp_06's canonical `ckpt/exp06/stats.json`: C − D = the descriptive row `cyl_or − control_hf` / hallway / c50 (fields `diff`, `nominal_two_way`; no convergence, no label), D − A = the descriptive row `control_hf − control` / hallway / c50 (same fields), C − A = `H1` (`diff`, `two_way`, `convergence`, `verdict`), C − F = `H1b` (same structure); from exp_09's `ckpt/exp09/stats.json`: E − A = `E1` (`diff`, `two_way`, `convergence`, `verdict`, `category`, `non_inferior_at_margin`). Rows are selected by contrast/room/metric assertions (never by list position), extant fields are copied exactly with their original meaning and interval convention, absent fields are `null` ("not recorded"), and each row records the source path, its sha256 and the selector; nothing is recomputed, no convergence is manufactured, and no descriptive row is reclassified as a decision.

**Overall reading (single, fixed in advance).** The fairness question is answered by **P3**: CERPA's advantage over an explicitly cue-equipped xRIR persists iff C − H is a detected improvement for C; whether H is non-inferior to C is a separate statement; a margin-sized advantage is a third. The reviewer's premise ("the improvement is due to the extra conditioning") is **assessed**, not refuted, by P4 and Q1 (does the explicit cue improve the vanilla xRIR at all?) together with P3; D and G are implicit-conditioning controls reported regardless of outcome, and D − A is not evidence about explicit conditioning. Equivalence failures (N3, P1, P2, Q1, Q3) mean insufficient precision or a real difference and are reported as such; no arm replaces another in the table on the basis of results. Absolute numbers remain non-comparable with the paper's Table 2 (exp_02).

**Paper table (fixed in advance).** Rows: xRIR = A (A′ shown as an external reference row labelled "released checkpoint", never substituting for A); xRIR + orientation cue = H (J as "adapter" supplementary row); Yaw-Augmented xRIR + orientation cue = I (K supplementary); CylindricalViT + orientation cue = C; frame-only controls D, G, F and E, B in the supplementary block.

**Outputs.** Separate phase outputs: `ckpt/exp11/phase1/{stats.json,summary.txt}` (arms A–G), `ckpt/exp11/phase1b/…` (+ J, K), and the final canonical `ckpt/exp11/{stats.json,summary.txt}` produced once every planned arm is complete (one run over all arms; `write_outputs` never overwrites; the phase files remain as interim records). The results page and analysis are rendered only from these files.

## 11. Amendments during implementation (logged in the notebook)

- **A1 (2026-09-27 09:3x, Planner decision after Codex close reviews 2–5 of round 2).** The per-arm publication lock of `tools/exp11_launch.sh` (requested by Codex close review 2 to serialise recovery and promotion) is a **kernel advisory lock**: `flock -n <arm-root>/.publish.lock` held by one process for the whole protected section (recovery: alias resolution → validation → finalization → promotion; full mode: from before the child launch through promotion). A second invocation fails immediately; the lock is released by the kernel when its holder exits or dies, so **no stale lock can exist and no stale-lock breaking, grace period, owner file, generation nonce, meta-lock or file barrier is implemented**. `--break-lock` is removed. Rationale: the pathname-based `mkdir` protocol accumulated five reviewed interleaving defects (close reviews 2–5) in an operator-convenience path; the kernel primitive is the standard, provable solution and removes the surface. Signal handlers stay terminating (128+n) with the `INTERRUPTED` guard; ownership-preserving abort, idempotent already-published recovery and `--replace-final` are unchanged. Roots are local (`ckpt/exp11/` on NVMe), where `flock` is reliable.
- **A2 (2026-09-28 05:1x, Planner decision after Codex close reviews 15–17).** The launcher's filesystem probe (`tools/exp11_pathprobe.py`, A1's successor design) **returns no path strings**. Verdicts carry only a mode (`present <mode-hex>` / `absent`) or a link classification (`link` / `notlink` / `nolink`); every decision that formerly compared a returned canonical path or link target with another path now asks the probe an IDENTITY question — `same <a> <b>` → `same` / `different` / unknown, decided in Python by device and inode of the followed stats (`os.path.samestat`), with a link's target resolved in-process. Log lines may print an informational `readlink` result but no decision depends on it. Rationale: three consecutive close reviews found residual gaps in the path-field grammar (relative paths, spaces, byte counts, terminal `..`, trailing slashes); a protocol that carries no paths has no such grammar. The trainer, in-process, uses the same Python identity primitives for arm containment (no string comparison of canonical fields).
