## Findings

1. **should-fix** — `tools/param_curve.py:210-217`. The bound `train_manifest` is not tied to the bound `train_completion` or to the checkpoint's attempt: the contract reads `train_completion.train_manifest_sha256` nowhere, and neither binding's path is compared with the checkpoint's directory (the `args.json` binding is, `:221-223`). *Demonstrated:* with S_simple's own `train_manifest.json` carrying an unapproved launcher digest and the five S_simple evaluations binding L_simple's `train_manifest.json` (approved digest) plus S_simple's real `completion.json`, `admit` returns **no deviation** (`test_adv_close.py::test_gap_train_manifest_not_tied_to_completion_or_checkpoint`). *Why:* A8's single-delta evidence is "the attempt that produced this checkpoint was trained by the approved launcher"; as written the producer proves "some bound manifest was". The live risk is a copy-paste slip across the 40 S/L eval launches (four arms × ten `--bind-input` pairs) being admitted silently rather than refused; the launcher's own fail-closed `full` path makes an actually-different launcher unlikely, so this is defence in depth, not a live hole. *Fix (2 lines inside the existing block, fixture already satisfies both):* after the loop, `require(training['train_completion']['train_manifest_sha256'] == fields['mutable_inputs']['train_manifest']['sha256'], 'train_completion binds train_manifest')` — the launcher writes `completion.train_manifest_sha256` from the digest it re-validates against the file at finalisation, so real artefacts pass; and inside the loop `require(bound_path.parent == (root / fields['checkpoint']).resolve().parent, name + ' binding path')`, mirroring `:223` (the `final` symlink resolves both to the attempt directory). Add one refusal test per check (swap the manifest; move a binding to another directory).

2. **nit** — `tools/param_curve.py:353` and `tests/test_param_curve_cli.py:98-102`. The adapter guard is an `assert`; under `python -O` it disappears and `publish` proceeds with a writer that never calls the exp_05 renderer (demonstrated: `python -O` with a stub `write_outputs` prints the adapter running). The documented invocation has no `-O`, but the guard exists precisely for the silent case. Use `if 'render_summary' not in write_outputs.__code__.co_names: raise RuntimeError(...)` and match `RuntimeError` in the test.

3. **nit** — `tools/param_curve.py:219` vs `:296`. `training['train_completion']['outputs'].get(epoch)` raises `AttributeError` when `outputs` is not a dict; `admit` catches `ValueError, TypeError, KeyError, OSError, IndexError` only, so a malformed completion crashes the run instead of producing a deviation (demonstrated with `outputs` as a list). The real launcher always writes a dict (`directory_listing`), so cosmetic. `require(isinstance(outputs, dict), 'train_completion outputs')` or add `AttributeError` to the caught tuple.

4. **nit** — `tests/test_param_curve.py:144-152`. The superiority construction (19 874 × −0.1, 126 × `upper`) is tight only from below and only for TARGETS_K8 (rank 19 875 is the first `upper`); for CURVE_K8 the rank 19 917 lies 42 positions inside the block, so a ±1 rank error is not detected there (measured: a −1 shift fails the two TARGETS cases only, a +1 shift fails none). The TOST test is tight in both directions thanks to its asymmetric 250 / 251 blocks (both shifts fail all four cases). The `upper == 0.` strict-inequality check — the point of the test — works. Tighter: `np.r_[np.full(rank - 1, -.1), [upper], np.full(20000 - rank, upper + 1)]` with rank 19 917 (family 6) / 19 875 (family 4).

5. **nit** — `tools/param_curve.py:164-165`. The verdict string still says "at the three tested tiers" while the count is `len(profile['pairings'])`; `test_dominance_requires_every_registered_pairing` shows "dominance supported … three tested tiers" for two pairings. Format the count into the string, or keep the literal and assert `len(pairings) == 3` where the profile is frozen.

6. **nit** — `tools/param_curve.py:107,111`. A yaw cell carries the same excluded list twice (`paired_cohort.excluded` and `excluded`). Harmless (0.43 MB total).

7. **nit (pre-existing, cosmetic)** — `tools/param_curve.py:197,297,315`. "re-evaluate M" can appear three times in one message for an M run with an unapproved evaluator (contract text, the per-directory suffix, the final append).
