## Findings

1. **should-fix** — `tools/param_curve.py:201-224` (`run_contract`, current-evaluator path) and `:240-241` (`admit`). The `closures.training_launcher` pin is required to be non-null but is never compared with any run artefact, and S/L runs are admitted without a `train_manifest` / `train_completion` binding (the eval launcher binds `train_args` automatically; the other two only via `--bind-input`, `tools/exp04_eval_launch.py:148,237-244`). *Why:* §2's single-delta contract — the four new arms trained by the same launcher closure — is what the tier curve rests on, and here four arms may be trained at different commits; exp_04's "recorded, not compared" precedent (`paired_compare.py:271`) covered one arm whose checkpoint pin was the evidence. The producer as written would admit an L arm trained by a different trainer than the S arm as long as its `args.json` recipe keys agree. *Fix (≈ 5 lines):* in the non-legacy branch `require('train_manifest' in names, 'missing train_manifest binding')`, read it through `read()` (its bytes are already bound by `admit_run`), and `require(tm['source_closures']['launcher']['sha256'] == pins['closures']['training_launcher'], 'training launcher closure')`; the fixture already writes `source_closures=dict(launcher=training)` with the matching pin, so the tests need only the two refusal cases (missing binding, mismatched digest). Alternatively, state in plan §4/§6 that the training-launcher pin is recorded only and the Planner verifies each S/L attempt's `train_manifest.json` closure at fill time — but then the producer's own JSON would carry an uncompared digest, which is what exp_04's Fable reviews criticised.

2. **should-fix** — `tools/param_curve.py:216-218`. The bound `args.json` is checked for `backbone, num_shot, epochs, batch_size, accum_steps, seed, yaw_aug, no_save` only; `lr, weight_decay, decay_epochs, lr_gamma, max_len, tf32` (§3 recipe; all present in exp_01's two M `args.json`, values 0.001 / 0.0001 / 3 / 0.1 / 9600 / true) are not. *Why:* the producer is the last gate before a verdict; the launcher's golden check protects the launch, not the analysis, and `_equal` already keeps float/int/bool distinct. *Fix:* extend the dict to `dict(num_shot=8, max_len=9600, lr=0.001, weight_decay=0.0001, decay_epochs=3, lr_gamma=0.1, epochs=12, batch_size=32, accum_steps=2, seed=0, tf32=True)`; both M files pass unchanged.

3. **should-fix (low)** — `tools/param_curve.py:327-328` (`publish`). The `FunctionType` re-binding of exp_04's `write_outputs` works only because the writer looks up `render_summary` as a module global (verified: `'render_summary' in write_outputs.__code__.co_names`). If exp_04's writer were ever refactored to obtain the renderer differently, exp_05 would silently publish exp_04's summary format with no error. *Fix:* `assert 'render_summary' in write_outputs.__code__.co_names` before building the adapter (or check that the written summary starts with the exp_05 label). Risk is low because exp_04's producers are pinned, but the failure mode is silent.

4. **should-fix (plan text; Planner, not Coder)** — plan §5 "Cohorts (registered)" bullet vs the amended H2 bullet — the inconsistency the Coder flagged. *What the code does:* `comparison()` computes the H2 target as the baseline arm's five-seed mean **on the cell's paired cohort** (`tools/param_curve.py:59-61,86`: `mask` from `cell_mask(a, e0_b=b)`, `target=float(means[1].mean())`), reports `baseline_own` = the baseline's own-cohort seed summary with its cohort sizes (`:72,77`), and the plotted curve points use each arm's own cohort (`curve_point`, `:35-52`). That is the amended H2 rule (§12 item 1, the counterexample). *What the generic bullet says:* "a plotted curve point, its seed SD **and every fixed target** use the arm's own cohort" — contradicting the H2 bullet. *Proposed wording for the generic bullet:* "a plotted curve point and its seed SD use the arm's own cohort — the queries finite for all five seeds of that arm and metric; a comparison cell — including the fixed target of an H2 cell, which is the baseline arm's five-seed mean on that cell's paired cohort — uses the paired cohort — queries finite for all five seeds in both arms of the cell. The baseline's own-cohort curve mean is displayed next to the target, labelled, with both cohort sizes (queries and rooms); …" (rest unchanged).

5. **nit** — `tools/param_curve.py:59,76`. `exclusions` keeps `cell_mask`'s `a` / `b` keys; exp_04's `_analyze_cell` maps them to role names. Map with `dict(zip(('a', 'b'), pairing))` so the JSON is self-describing.

6. **nit** — `tools/param_curve.py:158-159`. `supported == 3` hard-codes the tier count; use `len(profile['pairings'])`.

7. **nit** — `tools/param_curve.py:93-107,152-153`. Yaw cells carry no per-cell descriptive flag; the only markers are the summary header (`DESCRIPTIVE …`) and `profile.mode == 'yaw'`. Add `descriptive=True` (or `decision_driving=False`) to each yaw cell and copy `verdict_scope` into the result so the page generator cannot render a yaw cell as a decision.

8. **nit** — `tools/param_curve.py:22-26`. `cohort()` embeds the full retained-query list (6 337 strings) in every curve point and cell: ≈ 24 copies for a CURVE profile, ≈ 162 for YAW (tens of MB of canonical JSON). The excluded lists already identify the complement; a retained-set digest plus counts would suffice.

9. **nit** — `tools/param_curve.py:329-330`. `recheck_inputs` runs twice (in `publish` and inside the writer). Harmless.

10. **nit** — `tools/param_curve.py:287-289`. The "re-evaluate M" suffix also fires when the M runs are simply absent (the role name appears in the seed-set deviation). Apt, but "missing" would be clearer.

11. **nit** — `tools/exp05_profiles.py:83`. The loader accepts any non-empty `checkpoints.*.path`; equality with the profile path is enforced only at admission (`param_curve.py:246`, verified refused). A loader-level check would fail earlier, at fill time.
