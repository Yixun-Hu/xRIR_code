1. **should-fix (carry forward to round 2; no change to this round's files)** — `tools/yaw_aug.py:146-147` `YawAug.offsets_for` binds the run counter to the literal `batches_per_epoch=9261` through `counter`'s default (`:64`). This is exactly plan §2 (`t = (epoch − 1)·9261 + batch_idx`) and the banner text, so the module is per spec. The consequence for round 2: any training loader with more than 9 261 micro-batches (e.g. batch size < 32 for a full epoch) makes `counter(epoch, 9261)` raise `ValueError` at `batch_idx == 9261`, i.e. about 2.3 h into epoch 1 rather than at startup (verified: `counter(1, 9261)` → `ValueError("invalid epoch, batch index, or batches per epoch")`). Minimal fix, in `train_xRIR_backbone.py` when `--yaw-aug 1`: assert `len(train_loader) <= 9261` (and `== 9261` for the reportable arm at batch 32) before the banner is printed. `--max-train-batches` smokes are unaffected.

2. **nit** — strictness asymmetry inside the module: `_require_ints` (`tools/yaw_aug.py:43-45`, `type(value) is not int`) rejects NumPy integers and bools for every mixer/config argument (`counter(1, np.int64(0))`, `draw_offsets(np.int64(3), …)`, `YawAug(seed=np.int64(0))` all raise), whereas `rotate_scene_yaw_batch` accepts any `numbers.Integral` width (`:92`; `W=np.int64(512)` works and is bit-exact). Harmless and arguably the safer direction for the seeding path; heads-up for round 2 that `epoch`, `batch_idx`, `n` and the seed must be native Python `int` (argparse, `enumerate`, `tensor.shape[0]` all are).

3. **nit (test strengthening)** — `tests/test_yaw_aug.py:119` asserts the batch result matches the scalar `rotate_scene_yaw` to `atol=1e-6`, but the implementation is actually **bit-exact for float32** on CPU, cuda:0 and cuda:1 for every k in [0, 512) (my sweep, below); float64 differs by at most 1 ulp (8.9e-16) at 3 of 512 angles because torch's vectorised float64 `cos`/`sin` differ from `math.cos`/`math.sin` there (after the float32 cast they agree at all 512 angles). Suggest `torch.equal` for the float32 parametrisation and `allclose` only for float64, to lock in the stronger property the code already delivers. The norm-preservation check at `:128` (`atol=1e-6`, float32 magnitudes up to ~4) has roughly 2 ulp of headroom; deterministic at the fixed seed, but fragile if the fixture grows.

4. **nit (test)** — the device-mismatch case (`tests/test_yaw_aug.py:174`) uses the `meta` device. My probes confirm every real mix is refused with `ValueError` (geometry cpu / ks cuda:0; geometry cuda:0 / ks cpu; depth cuda:0 / src cpu; geometry cuda:0 / ks cuda:1; depth cuda:0 / refs cuda:1), so behaviour is correct; a CUDA-gated real-device case would document it.

5. **nit (test)** — `tests/test_yaw_aug.py:95-97` `test_apply_matches_batch_geometry_only` compares an alias with itself. The "audio untouched by construction" claim of plan §5 is fine as stated; if a pin is wanted, assert `inspect.signature(apply_yaw_aug).parameters` is exactly `(depth_coord, src_loc, ref_locs, ks, W)`.

6. **nit** — `rotate_scene_yaw_batch` forces the depth output contiguous (`:125`) but returns `src_loc'`/`ref_locs'` in the inputs' memory layout (non-contiguous when the inputs are; values bit-exact either way). Harmless; a `.contiguous()` for symmetry or a docstring note is optional.
