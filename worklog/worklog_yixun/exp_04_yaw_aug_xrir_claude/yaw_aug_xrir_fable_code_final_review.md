1. **should-fix (before any confirmatory evaluation is launched; touches the `writer` closure, so it must precede the A9 fill)** — `tools/exp04_eval_launch.py:28-48, 51-125` (`_run_child`, `execute_run`). What: the evaluation launcher installs no SIGTERM/SIGHUP handling and spawns the child in the launcher's own session. Reproduced with a sleeping stub child: SIGTERM → launcher exit −15, the run directory keeps its canonical name (no `completion.json`, no `_ABORTED_` rename), the log keeps its canonical name, and **the child keeps running orphaned**; SIGINT → `run_ABORTED_child_failed`, log renamed, child reaped (the `except BaseException` path works only for Python exceptions). Why: plan §4 schedules ≈ 17 h of unattended evaluation launches (the SOP's stop signal for an unattended job is `kill`, i.e. SIGTERM); an orphaned evaluator burns the GPU for up to 70 min while the directory looks live. No evidence is corrupted (the producers refuse a run without `completion.json`; verified: `run directory contents`), so this is robustness, not integrity. Minimal fix (≈ 6 lines): decorate `execute_run` (or wrap `main`) with `tools.exp04_launcher.termination_handlers()` so SIGTERM/SIGHUP raise into the existing abort path, use `start_new_session=True` for the child and `os.killpg` in the `finally` (as the training launcher does), and label the reason `terminated_<signal>`; test: the training launcher's `test_signals_abort_and_reap_sleeping_child` pattern. Interim operational rule if it is not fixed first: stop evaluation launchers with SIGINT only, and run them under `nohup setsid … > log 2>&1 &`.
