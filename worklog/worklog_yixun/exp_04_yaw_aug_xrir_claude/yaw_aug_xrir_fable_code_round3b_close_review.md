## Findings

Severity legend: blocker / should-fix / nit. None blocks the round; 1–3 are small and should land before the confirmatory launch (which cannot start before a GPU frees anyway).

1. **should-fix** — `tools/exp04_launcher.py:596-611` (`execute_attempt` abort path) and `:381-396` (`run_child` finally). What: the abort path is not signal-safe. A second SIGTERM/SIGHUP arriving while the first abort is being processed re-raises `LauncherTerminated` out of the `except` block: the child is already dead (killed in `run_child`'s `finally`), but `abort.json` is not written, the attempt and its log are **not renamed**, and **no hours are accounted** — the directory stays `attempt_<ts>` with `execution.json {child_exit_status: null}` (reproduced: SIGTERM, then SIGHUP while `abort_log` was running → listing `attempt_t/{effective_args, execution, train_inventory, train_manifest}.json`, `logs/train.log`, no `cumulative_hours.json`). The same window exists inside `run_child`'s `finally` (a signal between killing the child and killing the sink leaves `tee` alive). Why: an impatient `kill` twice or a `pkill -f` matching twice within the ≤ 5 s kill/wait window leaves an attempt that looks live, and its hours escape the 43 h ledger. Fix: make the handler idempotent — set a `terminating` flag on the first signal and ignore later ones (or `signal.pthread_sigmask(SIG_BLOCK, {SIGTERM, SIGHUP, SIGINT})` on entering the `except` block and `run_child`'s `finally`, restored by the context manager); test: SIGTERM then SIGHUP with `abort_log` patched to sleep, assert the `_ABORTED_terminated_SIGTERM` rename and the hours row.

2. **should-fix** — `tools/exp04_launcher.py:251-262` (`termination_handlers`). What: the handler is installed unconditionally, overriding an inherited `SIG_IGN`. Under `nohup <launcher>` (without `setsid`) Python inherits `SIGHUP = SIG_IGN`; the launcher re-arms it, so the terminal hangup that `nohup` exists to survive now **aborts the 30 h run** as `terminated_SIGHUP` (reproduced: `nohup python …` → inherited `Handlers.SIG_IGN`, inside the context → `terminate`). The `nohup setsid` template in `exp04_launch.sh` detaches from the terminal and is safe, so this is a footgun rather than a live defect. Fix (POSIX convention, two lines): do not install a handler for a signal whose previous disposition is `SIG_IGN`; test by setting `SIG_IGN` before entering the context and asserting `getsignal` is unchanged and `os.kill(SIGHUP)` is ignored.

3. **should-fix (required before `finalize` is ever used on the confirmatory attempt)** — `tools/exp04_launcher.py:502-549` (`finalize_attempt`). What: the "recorded execution evidence" is an unsigned `execution.json` inside the attempt, and `finalize` validates only its internal consistency.
