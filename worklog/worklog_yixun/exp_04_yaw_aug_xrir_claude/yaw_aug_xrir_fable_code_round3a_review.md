## Findings

Severity legend: blocker / should-fix / nit.

1. **blocker** — `tools/provenance.py:23-37` (`source_closure`). What: the closure subprocess inherits the launcher's environment, so `PYTHONPATH` is whatever the caller had; `sys.path.insert(0, repo)` only wins for modules that *exist* in `repo`. A repo-local module that is missing (or renamed) in `repo` but importable from another checkout on `PYTHONPATH` is imported from there and then **silently dropped** by the `f.startswith(repo + os.sep)` filter, so the closure and its digest are computed as if the dependency did not exist. Reproduced: a copy of `fce0035` with `tools/provenance.py` deleted and `PYTHONPATH` pointing at a full checkout → `source_closure('tools.exp04_eval', copy)` returns 13 files without `tools/provenance.py` and `closure_record` happily digests them (`e69cf694…`). Why it matters: the closure digest is the root of the whole evidentiary chain (evaluator handshake, completion, round-4 admission); a fail-closed design must not have a silent-omission mode, and the prompt said "as exp_03's binder does" — the binder pinned `env={**os.environ, "PYTHONPATH": repo}`. In the recorded runs `PYTHONPATH` was this repository only (the Coder's smoke manifest records `repo::repo`), so **every closure produced so far is complete** (I reproduced exp_03's 12-file list and digest, see Verified 2) — this is a latent hole, not a corrupted artefact. Minimal fix: run the subprocess with `env=dict(os.environ, PYTHONPATH=str(repo))` (drop the `''`/cwd entry too, e.g. `sys.path = [repo] + [p for p in sys.path if p]`), and make the filter fail-closed: every imported module file that is neither under `repo` nor under `sys.prefix`/`sys.base_prefix` (stdlib + site-packages) is a *foreign* dependency → raise with the list instead of dropping it. Test: the tmp-tree probe above must raise; `eval_yaw_rotation`'s closure must still equal exp_03's 12 files.

2. **should-fix** — `tools/exp04_eval_launch.py:141-152` (`build_fields`) and `tools/provenance.py:40-56` (`closure_record`), `tools/exp04_eval.py:65`. What: `--reviewed-commit` is used and recorded verbatim; `git show <ref>:path` / `git log <ref>..HEAD` accept abbreviated and symbolic refs, so the manifest may carry `"reviewed_commit": "fce0035"` (the Coder's own smoke does) or `"HEAD"` / `"main"` (both accepted by `validate_manifest` in my probe). Why: an "immutable" manifest whose reviewed commit is a moving ref is not a stable record, and exp_03's acceptance checker pins full SHAs. The check itself stays fail-closed (blob digests and `commits_after_reviewed` are recomputed and compared), so this is a record-quality defect. Fix: in `build_fields` resolve `git rev-parse --verify "<ref>^{commit}"` and store the 40-hex result; in `validate_manifest` refuse a `reviewed_commit` that is not 40 lowercase hex characters.

3. **should-fix (SOP item 9)** — `tools/exp04_eval_launch.py:80-90` (abort path). What: on any failure the run directory is renamed `<dir>_ABORTED_<reason>`, but the teed log in `--log-dir` keeps its plain name (`lbl_<ts>.log` after a child `SystemExit(3)` in my probe). The SOP requires aborted runs' logs to carry the `_ABORTED_<reason>` suffix, and exp_03's `run_start` treats a plain-named log as canonical. Fix: in the `except` block, if `log_path` exists rename it to `<stem>_ABORTED_<reason>.log` (best effort, before re-raising).

4. **should-fix** — `tools/exp04_eval_launch.py:68-78` (finalisation). What: finalisation checks only that the two outputs exist, revalidates the declared inputs and hashes; it never opens the outputs and does not look at the rest of the run directory. Probes: a stub child that also writes `rogue.txt` into the run directory gets a completion; outputs whose meta does not echo `eval_manifest_sha256` (my stub wrote `{}`) get a completion. Why: the plan makes the launcher the owner of finalisation; two cheap checks close the "trust the run's own claims" gap at the source — (a) the directory must contain exactly `{eval_manifest.json, per_sample_yaw.json, metrics_yaw.json}` before `completion.json` is written, (b) both metas must carry `eval_manifest_sha256 == digest`, `conditions == fields["conditions"]`, `n_samples == fields["n_samples"]`, and the `per_sample` query list must have `n_samples` entries.
